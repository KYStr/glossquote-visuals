# 新商業作品逐條驗收

自 M04 起，主責依同一候選 commit 審查。每件逐條寫 PASS、FAIL 或 NOT_RUN，附可重查的原始畫面、時間序列、流程輸出或命令報告、環境及具體觀察。全部 PASS 才可簽核。缺證據記 NOT_RUN，退回原製作對話時列規則 ID、重現條件及需改處。修改後將每條證據重新對齊最終來源。M01–M03 按當時規則留存。

| 規則 | 維度 | 通過條件 |
|---|---|---|
| ART-1 | 首屏辨識 | 1440×900、390×844 初次載入、不操作，品牌、供應項目、主要行動及 brief 指定的材質主體均可在首屏辨識；附兩張完整截圖及主責逐一指認。 |
| ART-2 | 材質與動作 | 正常動態模式前三秒可見 brief 指定的動作；比對首幀、過程與結束，逐一驗證各作品 brief 的指定物理觀察點；控制回到起始狀態時材質仍貼合。 |
| ART-3 | 作品辨識 | 並排檢視本批桌面與手機首屏，每件至少能指出三項具體差異（構圖、字體、色彩、材質、動作），且內頁商品或服務至少兩處延續相同視覺語言。 |
| GPU-1 | 即時輸出 | 隔離 WebGPU 成功建裝置，單一活動畫布有非空且隨時間改變的圖像；記錄 adapter、瀏覽器、版本、實際像素樣本，無 shader validation 或 runtime error。 |
| GPU-2 | 控制與凍結 | 桌機鍵盤、手機觸控可到各狀態並返回；暫停保留當幀，至少一秒無變化；繼續有後續動作。附實際影格與時間。 |
| PERF-1 | 畫面更新 | 在記錄的參考環境、1440×900 與 390×844 兩種 viewport，各暖機 2 秒後連測 10 秒。在效果持續運作區間量實際畫布更新／渲染提交間隔，兩種 viewport 均須 median ≤34 ms、p95 ≤50 ms、最長 ≤150 ms；列原始時間、adapter、DPR。rAF 回呼、影片編碼率或螢幕刷新率單獨均不足。 |
| PERF-2 | 資源 | 建置後每語首載含 lazy chunks gzip ≤2 MiB；離開首屏或背景化停止送幀，回返最多一個活動實例，無重複綁定或時間突然跳動。 |
| UI-1 | 版面 | 中英在 320、390、768、1440 CSS px 及桌面 200% 放大均無截字、重疊、水平溢出；CTA、選項、結果與控制完整可讀。 |
| UI-2 | 操作 | Tab 順序與畫面一致、焦點可見、主要控制熱區至少 44×44 CSS px；一般文字對比 ≥4.5:1、大字 ≥3:1。觸控不依賴 hover；選擇/錯誤/完成時能辨識當前狀態。 |
| BIZ-1 | 商品決策 | 每款有名稱、適用對象、規格或成分、數量或價格條件；兩語資訊對等。概念品牌、示意時段及離線結果如實標示。 |
| BIZ-2 | 客戶流程 | 依 brief 的正常、邊界、回改與輸出流程各走一遍；比對匯出內容與實際選擇、語言及數量；無假送出／付款成功。 |
| FALL-1 | 降級首屏 | 分別在 no-JS、WebGPU 初始化失敗、reduced motion 取證。三者首屏都能辨識材質、讀內容並找到下一步；減少動態預設靜止；GPU 失敗仍可操作商業流程。 |
| FALL-2 | 復原 | 模擬裝置遺失、快速暫停/恢復、離頁再回來，無空白遮蔽、卡死或未處理例外。 |
| SHIP-1 | 來源與隱私 | 鎖版 clean install、check/test/build 通過；檢查建置碼、請求與 storage，僅自託管、關閉 telemetry。雙語 URL、canonical、互返、OG、畫廊連結均正確。 |

主責為非作者。桌面與手機動態各留至少五個原始時間影格，覆蓋八秒和完整週期（持續演化則註明），另留控制及暫停前後。模擬手機須標明 viewport 與實際執行裝置。記錄參考平台；軟體渲染結果只能代表該環境。發布後另核對正式 URL、部署 SHA、兩語入口、可讀資產及 ZIP 校驗。
